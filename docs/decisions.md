# 设计取舍记录

> 这份文档是给面试用的：每条都写「当时有哪些选项 / 为什么选这个 / 代价是什么」。
> 不写"采用了 XX 先进技术"，写"放弃了什么"。

## D1. 为什么是复判，不是检测

| 选项 | 问题 |
|---|---|
| 重新做一遍缺陷检测 | 与客户既有 AOI 抢活，验收标准打架；且 AOI 的检出率客户已经接受，重做等于否定它 |
| 对 AOI 结果做图像后处理（客户最初诉求） | "后处理"无法定义验收标准：处理到什么程度算合格？ |
| **对已报 NG 做真伪二分类** | 验收标准单一可量化：这批 NG 里漏掉多少真缺陷 |

代价：把问题限制在 AOI 的召回范围内，AOI 漏掉的缺陷这个方案救不回来。这一点在方案里要主动向客户说明——**能力边界先说清，比事后扯皮便宜**。

## D2. 为什么旁路，不改 AOI 代码

改：能拿到更早的介入点（在 AOI 判定前就参与），但需要客户开放 C++ 源码或提供 SDK，改完要重新验证整条链路，故障责任不清，回滚需要停机。

旁路：多一次图像落盘/传输的 IO 开销，多一跳网络延迟；换来的是**上线失败可以无声退回**——把交付风险从"客户产线"转移到"我们自己的服务"。

在 toB 项目里，能不能回退往往比性能更重要。

## D3. 为什么用分类头，不用检测头

前提是 AOI 已经把缺陷框裁出来了，位置信息已知。
- 分类头：输入就是一张 crop，输出一个概率，算力和延迟最省。
- 检测头：要重新回归框，标注成本高一个量级（要画框），且框的质量直接决定效果。

如果 AOI 只给整图、缺陷位置未知，那必须换检测头——这是方案的**前置假设**，接新客户第一件事就是确认这个。

## D4. 不做类别重采样，把不平衡交给阈值

重采样（过采样少数类 / 欠采样多数类）会改变先验，模型输出的概率就不再对应产线真实分布。后果是：阈值失去业务含义，客户问"这个 0.7 是什么意思"答不上来。

做法：保持原始分布训练 → 推理时按**期望代价最小**选阈值：

```
E[cost](τ) = C_fn · FNR(τ) + C_fp · FPR(τ)
```

好处是 τ 变成一个**可以和客户谈的旋钮**：客户说"最近返工太多，宁可多看几张"，就把 C_fn 调大，τ 自动下降。这比"我们调了调参"专业得多。

## D5. 合成伪缺陷的两个坑

1. **shortcut learning**：如果伪缺陷样本全是加了扰动的图，模型会学"有没有扰动痕迹"而不是"像不像缺陷"。缓解：保留约 20% 未扰动的正常图混进伪缺陷类，让两类在"扰动程度"上有重叠。
2. **强度分布不匹配**：合成扰动的强度是拍的，现场是真实分布。缓解：扰动强度随机化并覆盖较宽区间；上线后用真实过杀样本做一次阈值重标定（这一步在原项目里做过，本仓库无法复现）。

**这是本仓库最大的方法论弱点，我主动交代**：合成数据的模型上限，取决于合成器有多像现场。

## D6. 数据划分按拍摄批次，不按图

同一块组件切出来的电池片外观高度相似。随机切图 → 测试集里有"训练集同款"，指标虚高几个点，上线就崩。

本仓库按 ELPV 文件名里的拍摄时间戳分组，整组进同一个 split。这是工业视觉数据集最容易踩的坑之一。

## D7. 服务出错必须 pass_through

旁路服务的第一原则：**它挂了，产线要能当它不存在**。所以 `/recheck` 内部兜住所有异常，返回 `pass_through`，由产线退回人工复核。宁可退化成原来的流程，也不要卡住产线。

代价：错误会被静默吞掉，所以必须配 `/metrics` 暴露 pass_through 比例——这个比例升上去就是告警信号。
